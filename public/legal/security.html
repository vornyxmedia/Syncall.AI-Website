Security Overview

syncall.ai | Last updated 20 October 2026

syncall.ai is a marketing analytics service operated by Vornyx Media LLP, hosted on a Hostinger virtual private server in India (Mumbai). This overview explains how our application safeguards help keep accounts and workspace data secure, the role of the hosting infrastructure, and how connected services handle information.

Account and password protection

Account passwords are stored as salted, one-way Argon2id hashes rather than readable passwords. The application checks a submitted password against its stored hash when you sign in.

Sign-in requires a verified email address. Repeated incorrect password attempts trigger a temporary account lockout. Invalid sign-in attempts receive a generic error message, helping to limit disclosure of account details.

Password-reset links use randomly generated tokens with an expiry time. The application rejects expired or previously used links. Completing a password reset invalidates existing sessions. Changing your password while signed in requires your current password and revokes your other sessions.

Sign-in sessions and browser safeguards

Sign-in uses randomly generated session tokens checked against server-side records. Sessions expire, and the application rejects expired sessions. You can review session details and revoke other sessions from your account security settings.

The sign-in cookie is marked HttpOnly, preventing ordinary browser scripts from reading it, and SameSite=Lax, which limits when browsers send it with cross-site requests. In production mode, the cookie also has the Secure flag, so browsers send it only over HTTPS.

The logout flow removes the server-side session and clears the browser cookie. The current app also clears its in-memory query cache during logout. Authenticated API responses carry a no-store instruction to reduce browser caching of account data.

Workspace data separation

Private analytics, dashboard and connector operations require an authenticated session. The application derives the workspace identifier from the signed-in account's membership and uses it to scope data queries and changes.

These application-level checks are designed to keep one workspace's data separate from another's. They do not imply that every user has a separate database or that every feature has a complete set of role-based permissions.

A shared dashboard link is a separate access mechanism: a person with the link may view the content it exposes without signing in. Treat such links as sensitive and use an expiry date where available.

Connections and information sent to providers

Supported OAuth connections use the connected platform's authorisation process. The connector implementation associates each connection with a workspace and checks that association when saving it. Integration availability depends on the provider and the configured service.

The Nango webhook endpoint checks a cryptographic signature before processing connection events and rejects requests when the required signing secret is missing. Disconnecting a source stops future syncing through that connection; you can also revoke access in the provider's own account settings.

When enabled and used, Ask your data sends your question, supplied conversation history, workspace data-coverage information and relevant metric results to Anthropic to generate an answer. Its predefined data-query tools are scoped to your workspace. Avoid including passwords, API keys or unnecessary personal information in questions.

Connected platforms and agency controls

Connections request read-only permissions limited to reporting data. The application never posts, edits, spends or sends messages on a connected platform. Access tokens are held by our self-hosted connection service rather than a third-party aggregator, and every platform request goes through it.

Connecting or disconnecting a platform, choosing which accounts sync, and creating or changing clients are restricted to organisation admins. Each of these actions is recorded in the activity log with the user, time and IP address. Admins receive an email when a connection is revoked and needs to be reconnected. Disconnecting a login deletes its stored token.

CRM and email platforms are read for totals only, such as contacts created or deals won per day. Individual contact records are not copied.

Request handling and security records

The API uses security response headers and a configured browser-origin policy. Input checks validate account forms, connector settings and analytics requests before processing. Upload endpoints apply file-size limits, and database access uses Prisma queries and parameterised SQL in the reviewed analytics paths.

The application records selected security events, including sign-in successes and failures, password changes, resets and session revocations. Records can include the event time, account identifier and IP address. Session records also include browser details. These records support investigation; they are not a claim of continuous monitoring or an immutable audit trail.

Hosting and data protection

syncall.ai currently runs on a Hostinger virtual private server in Mumbai, India. The application, its database, uploaded files and our self-hosted connection service run on that server. We plan to move hosting to Google Cloud in India, and we will update this overview and the Sub-processors list before we do.

HTTPS protects data travelling between your browser and the service. We do not claim that data stored on the server is encrypted at rest by the hosting provider.

Hostinger is responsible for its data centre and the virtualisation layer. Vornyx Media LLP is responsible for the server's operating system, the application and the settings it controls, including administrator permissions, service credentials, network access and data handling.

Production access controls, the selected storage region, backup schedules, restore testing and monitoring remain subject to deployment verification. This overview does not promise a specific backup retention period, recovery time, India-only data residency or uninterrupted availability.

The safeguards above describe the current application implementation. Production deployment checks and end-to-end security verification remain outstanding. This document is an overview, not a security certification or a service-level agreement.

Your part in keeping data secure

Use a unique password and keep access to your email account secure. Sign out on shared devices, review unfamiliar sessions and revoke access that is no longer needed. Upload only data you are authorised to use, and limit it to what is needed for your analysis.

Keep connected-platform permissions and shared links under review. The Privacy Policy explains personal-data handling and retention; the Terms of Service explain account responsibilities and use of the service.

Reporting a security concern

For suspected account misuse or a security issue, contact support@syncall.ai. For concerns involving personal data, contact privacy@syncall.ai. Include the affected feature, approximate time and a brief description so the issue can be investigated.

Do not send passwords, session cookies, access tokens or unnecessary customer data in a report. If you suspect your password is compromised, change it and revoke other sessions.
